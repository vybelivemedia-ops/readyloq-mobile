PATCH `/inspections/:id` authorization was a P1 same-company integrity gap: direct-ID tenant predicates prevented cross-company access, but did not prevent technician-to-technician status/signature tampering. Sensitive PATCH fields, `POST /:id/complete`, and `DELETE /:id` now share the owner-or-manager check; the latter was protected because it can destroy the record linking associated evidence. Same-company notes/site-metadata edits remain collaborative. The POST body can no longer make a technician the owner of another user's new inspection; manager/owner assignments must target a current same-company technician. Tests exercise direct IDs without list filtering. DELETE does not automatically remove stored objects.
