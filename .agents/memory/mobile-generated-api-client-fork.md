## The gotcha
`artifacts/readyloq-app/lib/api-client/generated/` (used by the Expo mobile app) is a manually-frozen fork of Orval output — it is genuinely divergent in size and ordering from `lib/api-client-react/src/generated/` (the one `lib/api-spec`'s `pnpm run codegen` actually regenerates). Running codegen in `lib/api-spec` does NOT touch the mobile copy.

**Why this exists:** unclear/historical — possibly the mobile client was forked at some point to hand-tune something and never reconnected to the pipeline.

**How to apply:** whenever you add or change a field in `lib/api-spec/openapi.yaml` that the mobile app also needs (e.g. a new column exposed on an existing entity), you must ALSO hand-edit the matching interface(s) in `artifacts/readyloq-app/lib/api-client/generated/api.schemas.ts` — regenerating/overwriting that file is out of scope and risky (it would blow away the fork's other differences). Grep for the type name there to find the exact interface(s) to patch.

Separately: several mobile features (schedule, products, treatment-logs, property-profile/property-visit) don't use the generated client at all — they have hand-written fetchers in `lib/api-client/*.ts` (not `generated/`). When adding a new endpoint that's schedule/products/treatment-log-shaped, check whether a sibling hand-written fetcher pattern already exists before assuming you need Orval-generated types.
