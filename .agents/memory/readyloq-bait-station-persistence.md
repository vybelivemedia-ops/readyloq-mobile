# Bait station persistence (added July 2026)

## Key types
- `LocalBaitStation` in `inspection-store.ts` — extends the UI BaitStation with `serverId?: number`
- `LocalInspection.baitStations: LocalBaitStation[]` — always initialized (??= [] fallback for old records)
- UI `BaitStationPanel` still uses its own internal `BaitStation` type; `LocalBaitStation` is a structural superset

## Write-through pattern
Every add/update/remove handler in `new-inspection.tsx` calls `updateLocalInspection` inside the setState callback so local storage is always in sync with component state. Resume loads `rec.baitStations` into component state.

## Sync (engine.ts step 5.5)
- Stations without `serverId` → POST to `/api/inspections/:id/bait-stations` → save returned id as `serverId`
- Stations with `serverId` → PATCH to keep server current
- Wrapped in per-station try/catch: bait station errors never block the main sync path

## API client
`lib/api-client/bait-stations.ts` — thin non-generated wrappers using `customFetch` directly

**Why not use the generated client?**
The generated api.ts is auto-generated by orval; editing it gets overwritten. Custom routes belong in separate files.
